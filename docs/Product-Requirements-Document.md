## 1. 产品概述

### 1.1 背景与问题

个人用户在管理 ACGMN（Anime 动画、Comic 漫画、Game 游戏、Music 音乐、Novel 小说）资源时，普遍面临以下痛点：

- **资源分散**：本地文件、网络硬盘、云盘等各处存放，管理混乱。
- **识别困难**：大量资源文件名是罗马音/缩写，难以直观看出是什么内容。
- **检索低效**：资源数量庞大（数十万级）时，搜索很慢。
- **功能割裂**：获取作品信息、匹配字幕、把文件和剧集对应起来等操作，需要多个工具配合，缺少统一平台。
- **扩展受限**：固定功能的产品无法满足用户各种各样的个性化需求。

### 1.2 产品定位

Ikaros 是一款**自托管（Self-hosted，即部署在自己电脑或服务器上）、面向个人用户的 ACGMN 内容管理系统**，提供从资源接入、信息管理、搜索、播放到收藏追踪的一站式管理能力。本体只提供最基础的核心功能，其余附加能力通过**插件系统**（像手机 App 一样按需安装的扩展模块）扩展。

### 1.3 产品目标

1. **统一管理**：所有 ACGMN 资源由统一平台管理，消除资源分散问题。
2. **信息完备**：为每个作品提供名称、中文名、封面、简介、评分等信息，支持从第三方平台同步。
3. **毫秒级搜索**：即使有数十万资源，也能瞬间搜出结果。
4. **可扩展**：通过插件机制开放能力边界，社区共建生态。
5. **多端覆盖**：提供网页控制台，并支持 Windows、Android 等主流平台客户端。

### 1.4 非目标（Non-Goals）

- 不提供公网多用户 SaaS 服务（定位为个人使用，不建议公网访问）。
- 不直接提供内容下载/版权内容分发能力。
- 不内置具体第三方信息源实现（由插件提供）。

### 1.5 免责声明

- 本程序为开源软件（AGPL-v3.0 协议），源代码公开可查。
- 本程序用于辅助**个人**管理资源，类似「服务器 + 客户端」模式的资源管理器。
- 仅供个人使用，不建议允许公网访问；用户行为与程序及开发团队无关。

## 2. 目标用户与使用场景

### 2.1 目标用户

| 用户类型 | 描述 | 核心诉求 |
|----------|------|----------|
| ACGMN 收藏爱好者 | 拥有大量本地番剧、漫画、音乐、小说资源的个人用户 | 统一管理、快速检索、自动获取作品信息 |
| 媒体服务器自建用户 | 熟悉自托管服务的用户（如 Jellyfin/Emby 用户） | 部署简单、可扩展、多端播放 |
| 开发者/贡献者 | 希望扩展 Ikaros 能力的开发者 | 插件开发、二次开发 |

### 2.2 核心使用场景

1. **资源接入**：挂载本地磁盘/网络硬盘目录，自动扫描、识别并归类到对应作品。
2. **作品管理**：创建/编辑动画、漫画、游戏、音乐、小说等作品，维护名称、封面、简介等信息。
3. **资源匹配**：把目录/文件与作品的剧集批量对应起来（支持多种常见命名格式，如 `[01]`、`EP01` 等）。
4. **搜索浏览**：通过名称、中文名、类型、标签等条件快速找到作品。
5. **收藏追踪**：标记想看/在看/看过/搁置/抛弃，评分评论，追踪追番进度。
6. **播放消费**：通过网页/App 在线播放视频（支持字幕、记住播放进度）。
7. **音乐聆听**：管理音乐专辑/歌曲，支持 DSub、音流等主流第三方音乐 App 直接接入播放。
8. **通知推送**：剧集更新时通过邮件等渠道接收更新通知。

## 3. 术语说明

| 术语 | 说明 |
|------|------|
| 条目 | 一部作品的基本单位，如一部动画、一本漫画 |
| 剧集 | 作品的组成部分，如番剧的第 1 集 |
| 附件 | 存放于本地的文件资源（视频、字幕、图片等） |
| 存储驱动 | 一种文件存放方式的统称，如「本地磁盘目录」「网络硬盘」；系统通过它可以访问文件 |
| 绑定 | 把目录/文件与作品的剧集对应起来 |
| 收藏 | 用户对作品的收藏状态（在看/看过等）及评分评论 |
| 条目关系 | 作品之间的关联（前传、后传、同世界观、原声带等） |
| 标签 | 用户/系统为作品、附件添加的分类标记 |
| 元数据 | 作品的描述信息（名称、封面、简介、评分等） |
| 插件 | 扩展 Ikaros 能力的独立模块，按需安装 |
| 命名规则 | 从文件名识别出「第几集」「是 OP 还是 ED」的规则 |
| 两步验证（2FA） | 登录时除密码外，再输入一次 6 位动态验证码，双重确认身份 |

## 4. 产品功能需求

### 4.1 功能总览

Ikaros 由三部分组成：

1. **客户端**：网页控制台（管理界面）、Windows/Android App、第三方音乐播放器。
2. **核心服务**：负责登录、作品、剧集、文件、收藏、搜索、标签、绑定、音乐、后台任务、通知、插件、设置等一切功能。
3. **数据存储**：数据库与文件存储（具体使用什么技术，见设计文档）。

### 4.2 登录与用户管理

#### 4.2.1 用户登录（FR-AUTH-01）

- **描述**：用户通过账号密码登录系统。
- **需求点**：
  - 支持用户名 + 密码登录。
  - 登录状态默认保持 3 天，可自动续期至 3 个月（无需频繁重新登录）。
  - 支持 **两步验证（2FA）**：登录时若已开启，除密码外还需输入 6 位动态验证码（每 30 秒更新一次）。
  - 个人中心支持两步验证的开启/关闭/重新绑定，支持主流验证器 App（如 Google Authenticator、Microsoft Authenticator）扫码绑定。
  - 支持退出登录；删除账户后自动退出登录。

#### 4.2.2 用户管理（FR-AUTH-02）

- **描述**：管理员对系统用户进行管理。
- **需求点**：
  - 用户列表查询、创建、编辑、删除用户。
  - 支持更新用户名、昵称、密码。
  - 支持为用户分配角色。
  - 非管理员用户看到的菜单和按钮，按其权限自动显示或隐藏。
  - 修改个人资料时，系统以当前登录账号为准，防止越权修改他人信息。

#### 4.2.3 角色与权限（FR-AUTH-03）

- **描述**：基于「角色-权限」模型的权限控制。
- **需求点**：
  - 系统内置角色：MASTER（主角色，默认拥有全部权限）。
  - 角色的新增、编辑、删除，以及角色与权限的绑定管理。
  - 权限可细分到具体功能模块（如作品、剧集、文件、标签、用户、角色等）。
  - 支持按模块为角色配置细粒度权限。
  - 控制台权限提示清晰明确，默认选择主角色。

### 4.3 条目（作品）管理

#### 4.3.1 条目模型（FR-SUBJ-01）

- **描述**：条目是 ACGMN 内容的核心单位。
- **字段说明**：
  - 类型：ANIME（动画）、COMIC（漫画）、GAME（游戏）、MUSIC（音乐）、NOVEL（小说）、REAL（真人）、OTHER（其他）。
  - 名称（必填）、中文名称。
  - 信息框：以结构化方式展示的作品详细信息。
  - 简介。
  - 是否成人内容（标记后不会出现在未登录的搜索结果中）。
  - 播出/发售时间。
  - 封面（支持保存到本地）。
  - 综合评分（0-10 分）。

#### 4.3.2 条目操作（FR-SUBJ-02）

- **需求点**：
  - 条目的新增、编辑、删除、详情查看。
  - 列表/条件查询：支持按名称（模糊搜索）、中文名、类型、标签、评分、日期等条件组合查询。
  - 支持「类型:动画」这类精确筛选格式。
  - 新增条目时自动检测剧集，没有剧集时自动创建默认剧集。
  - 删除条目时，自动清理关联的收藏、封面引用等。
  - 条目信息变更后，自动更新搜索索引、封面与缓存。
  - 多人同时编辑同一条目时，系统提示冲突，避免互相覆盖。

#### 4.3.3 条目关系（FR-SUBJ-03）

- **描述**：管理作品之间的关联关系。
- **关系类型**：前传（BEFORE）、后传（AFTER）、同世界观（SAME_WORLDVIEW）、原声带（OST）、OVA、OAD 等。
- **需求点**：
  - 条目关系的增删改查。
  - 控制台条目详情页以页签形式展示不同关系类型。
  - 关系变更时自动维护关联条目的状态。

#### 4.3.4 条目同步（FR-SUBJ-04）

- **描述**：从第三方平台（如番组计划 Bangumi）同步作品数据。
- **需求点**：
  - 支持按「平台 + 平台 ID」查询/拉取作品。
  - 第三方同步逻辑可重构、可扩展（由插件提供具体平台实现）。
  - 快速拉取作品后支持定位到对应条目。
  - 同步时自动下载封面到本地。
  - 大量同步时自动去重，避免重复条目。
  - 支持同步收藏进度（如番组计划平台的收藏进度）。
  - 同步失败时保留原封面不更新。

### 4.4 剧集管理

#### 4.4.1 剧集模型（FR-EP-01）

- **描述**：剧集是条目的子单元。
- **核心字段**：所属条目、剧集序号（支持小数，如 1、1.5）、分组、绑定的资源。
- **剧集分组**：正片（MAIN）、PV（宣传片）、OP（片头曲）、ED（片尾曲）、SP（特别篇）、小剧场、Live、CM（广告）、OST（原声带）、OVA、OAD、音乐碟 1~5、其他。

#### 4.4.2 剧集操作（FR-EP-02）

- **需求点**：
  - 剧集的增删改查。
  - 按条目查看剧集列表（支持分页）。
  - 批量创建/更新剧集。
  - 剧集排序（按序号，支持小数）。
  - 剧集序号支持 `1`、`01`、`1.5` 等格式。
  - 更新剧集时保持标识稳定（不因更新而改变）。
  - 常用数据自动缓存，查询更快。

#### 4.4.3 剧集序号识别规则（FR-EP-03）

- **描述**：从文件名自动识别「这是第几集、是正片还是特典」的规则。
- **需求点**：
  - 内置多种常见命名格式：`[01]`~`[100]`、`[EP01]`~`[EP100]`、`[01v2]`~`[100vX]`、空格包裹的 ` 01 `~` 99 `、`EP01`、`-01-`、`_01_` 等。
  - 特殊标记自动归类：`[NCOP]`→OP、`[NCED]`→ED、`[SP]`→SP、`[CM]`→CM、`[OVA]`→OVA、`[OAD]`→OAD。
  - 带编号的特殊标记：`[NCOP01]`~`[NCOP100]`、`[NCED01]`~`[NCED100]` 等。
  - 规则按优先级执行，通用兜底规则优先级最低。
  - 内置规则与插件规则合并执行，插件可扩展自定义命名规则。
  - 控制台提供命名规则管理页面：列表、启用/禁用、编辑、删除、详情、测试（输入文件名即可预览识别结果）。

### 4.5 附件（文件）管理

#### 4.5.1 附件模型（FR-ATT-01）

- **描述**：附件是系统管理的文件资源。
- **核心字段**：名称、类型（视频/字幕/图片等）、文件大小、文件指纹（用于检测文件是否变化）、存放位置、所属存储驱动、最后修改时间、创建/更新时间。

#### 4.5.2 存储驱动（FR-ATT-02）

- **描述**：存储驱动是文件访问的统一方式，支持挂载本地磁盘目录、网络硬盘。
- **需求点**：
  - 驱动类型：本地磁盘（LOCAL）、插件提供的存储类型（PLUGIN）。
  - 驱动的增删改查：新增、编辑（修改配置后自动重新挂载）、删除、启用/禁用。
  - 挂载时校验路径：拒绝不存在、不可访问、不是目录的路径。
  - 安全防护：附件只能访问自己存储目录内的文件，无法越权读取电脑上的其他文件（防止通过特殊路径或链接绕过）。
  - 驱动附件必须关联有效的驱动。
  - 插件可扩展新的存储方式。

#### 4.5.3 附件操作（FR-ATT-03）

- **需求点**：
  - 附件列表/条件查询：名称模糊搜索（支持多个关键词）、按名称/更新时间/文件大小排序。
  - 附件上传：普通上传、大文件分片上传（支持断点续传）、图片裁剪后上传。
  - 附件删除（删除时校验引用关系，防止误删）。
  - 附件播放读取：支持视频拖动播放时按需读取，拖动流畅。
  - 附件访问地址：独立解析，支持带条件参数获取。
  - 文件指纹：后台自动计算（不卡界面），期间校验文件状态，按文件大小和修改时间判断是否需要重新计算。
  - 目录刷新：自动扫描目录，只处理新增/变更/删除的文件（刷新更快）；重复的刷新请求自动合并。
  - 附件标签：支持为附件打标签（标签能力见 4.9）。

#### 4.5.4 附件关系与引用（FR-ATT-04）

- **描述**：附件之间的关联，以及附件与作品的引用。
- **需求点**：
  - 附件关系：支持手动把视频和字幕绑定在一起。
  - 字幕自动匹配：当剧集新增视频时，自动按文件名模糊匹配同名字幕文件（支持 ssa 等常见字幕格式）。
  - 附件引用：附件与作品/剧集的引用关系管理（如封面、剧集资源、用户头像）。
  - 批量绑定/解除绑定：按文件名→剧集序号自动批量匹配（支持三位数集数、小数集数如 1.5）。
  - 附件关系变更后自动联动更新。

### 4.6 目录绑定导入流程（Binding）

#### 4.6.1 概述（FR-BIND-01）

- **描述**：把本地目录（含资源文件）与作品/剧集自动匹配的**半自动化导入流程**。把目录交给系统，系统按步骤自动完成识别、建条目、绑定剧集；任一步骤失败时自动回退，不会留下半成品。

#### 4.6.2 导入步骤

| 顺序 | 说明 |
|------|------|
| 1 | 解析目录名，提取作品名称、剧集序号等信息 |
| 2 | 清理目录名（去除无效字符） |
| 3 | 查找本地已有的作品 |
| 4 | 获取作品信息并创建条目 |
| 5 | 创建条目标签 |
| 6 | 列出目录内文件 |
| 7 | 从第三方平台同步作品（对接番组计划等） |
| 8 | 批量绑定剧集与文件 |
| 9 | 处理 SP 等特殊子目录 |

#### 4.6.3 需求点

- 导入记录会持久保存，可随时查询导入进度。
- 记录每一步的执行状态（进行中 / 成功 / 失败）与错误信息。
- 失败时自动回滚已完成步骤（按相反顺序）。
- 支持按条件跳过某些步骤。

### 4.7 收藏

#### 4.7.1 条目收藏（FR-COLL-01）

- **描述**：用户对作品的收藏状态管理。
- **收藏类型**：WISH（想看）、DOING（在看）、DONE（看过）、SHELVE（搁置）、DISCARD（抛弃）。
- **需求点**：
  - 收藏操作：新增收藏、更新收藏类型、移除收藏。
  - 收藏评分（0-10 分）与评论。
  - 按条件查询收藏：分页、按日期、按收藏类型、按作品查询。
  - 收藏列表批量查询优化（大量收藏时响应更快）。
  - 收藏新作品时，自动为其剧集创建收藏（默认全部未看）。
  - 作品被移除时自动清理对应收藏。
  - 作品收藏类型变更时，自动联动更新剧集收藏状态。

#### 4.7.2 剧集收藏（FR-COLL-02）

- **描述**：追踪每一集的观看进度。
- **需求点**：
  - 标记单集已看/未看（「看完」按钮动态显示）。
  - 支持批量标记。
  - 剧集列表收藏（如歌单收藏）。
  - 收藏页默认显示「在看」的内容。

#### 4.7.3 历史记录（FR-COLL-03）

- 支持按日期范围查询历史收藏记录。

### 4.8 搜索

#### 4.8.1 全局搜索（FR-SEARCH-01）

- **描述**：毫秒级全文搜索（内部使用索引技术，细节见设计文档）。
- **需求点**：
  - 作品索引：名称、中文名、类型、标签、封面等纳入搜索。
  - 支持重建搜索索引（数据异常时可手动重建）。
  - 作品新增/更新/删除/标签变更后，自动维护索引，无需手动操作。
  - 支持按需开关索引初始化。
  - 启动时自动初始化全部作品的索引。

#### 4.8.2 搜索能力（FR-SEARCH-02）

- 分页搜索作品，返回名称、封面等命中信息。
- 未登录用户只能搜索非成人内容。
- 支持关键词组合与属性限定。

### 4.9 标签

#### 4.9.1 标签管理（FR-TAG-01）

- **描述**：为作品/附件提供标签能力。
- **需求点**：
  - 标签的增删改查（创建时校验唯一性并关联用户）。
  - 区分标签类型。
  - 作品标签的查询、添加、移除。
  - 自定义标签高亮显示。
  - 附件标签支持。
  - 插件可调用标签能力。
  - 作品标签变更后自动更新搜索索引。

### 4.10 插件系统

#### 4.10.1 插件生命周期（FR-PLUGIN-01）

- **描述**：插件是 Ikaros 扩展能力的核心机制，本体只提供基础功能，其余按需安装。
- **需求点**：
  - 插件安装：上传插件包安装（会校验文件名等安全风险）、从插件仓库安装。
  - 插件卸载、启用、禁用、升级。
  - 插件配置：以配置项形式读写（创建/更新/变更自动生效）。
  - 插件运行模式：正式部署模式 / 开发模式。
  - 插件版本与系统版本兼容性校验，不兼容时明确提示。
  - 插件之间相互隔离、互不干扰，也支持共享部分能力。
  - 安装失败、升级失败等异常情况有明确提示。

#### 4.10.2 插件扩展能力（FR-PLUGIN-02）

| 扩展能力 | 说明 |
|--------|------|
| 新的存储方式 | 插件提供自定义文件存储驱动 |
| 文件访问地址 | 插件自定义附件访问地址的生成方式 |
| 作品信息源 | 插件对接第三方作品信息平台查询作品 |
| 标签能力 | 插件查询/添加标签 |
| 作品同步 | 插件对接第三方平台同步作品 |
| 命名规则 | 插件注册自定义文件名识别规则 |
| 后台任务 | 插件注册后台执行的任务 |
| 自定义功能 | 插件提供自己的功能页面/服务 |
| 自定义数据 | 插件定义新的数据类型与内容结构 |

#### 4.10.3 插件安全（FR-PLUGIN-03）

- 插件可调用的内部功能中不提供删除能力（安全考虑）。
- 插件访问受权限控制。
- 插件安装时校验文件名，防止恶意文件（此为「插件安装安全校验」需求的唯一来源，NFR-SEC-08 引用本条）。

### 4.11 音乐模块

#### 4.11.1 概述（FR-MUSIC-01）

- **描述**：音乐资源管理模块。
- **核心概念**：
  - 专辑（对应作品模型中的音乐类型）。
  - 歌曲（对应剧集模型）。

#### 4.11.2 功能需求

- 专辑管理：专辑列表、详情（曲目列表）、新增、编辑、删除。
- 歌曲管理：歌曲的增删改查。
- 歌单：歌单对应剧集列表，歌单可收藏。
- 音乐碟分组：音乐碟 1~5。
- 控制台音乐页面：专辑管理、歌曲管理，支持中英文界面。

### 4.12 第三方音乐播放器兼容（Subsonic）

#### 4.12.1 概述（FR-SUBSONIC-01）

- **描述**：兼容 Subsonic 开放协议，允许 DSub、音流等主流第三方音乐 App 直接接入 Ikaros 播放音乐。

#### 4.12.2 支持的能力

| 分类 | 能力 |
|------|------|
| 浏览 | 歌手 / 专辑 / 歌曲 / 专辑列表 |
| 播放 | 音频流播放、封面获取 |
| 歌单 | 查看 / 创建 / 删除歌单 |
| 其他 | 搜索、播放记录、连接测试 |

### 4.13 后台任务系统

#### 4.13.1 概述（FR-TASK-01）

- **描述**：后台任务的调度与执行管理（如目录刷新、文件指纹计算等耗时操作在后台进行，不阻塞使用）。
- **需求点**：
  - 任务模型：任务状态、执行进度、日志。
  - 同时执行的任务数量可配置（默认最多 40 个）。
  - 任务的列表/详情/删除（支持分页与状态筛选）。
  - 插件可注册后台任务。
  - 系统启动时自动初始化系统任务。
  - 运行日志自动滚动保存（单文件最大 10MB，共保留 1GB，保留最近 2 份）。

### 4.14 通知系统

#### 4.14.1 邮件通知（FR-NOTIFY-01）

- **描述**：通过邮件发送系统通知。
- **需求点**：
  - 邮件发送设置（服务器地址、端口、账号、密码等），支持在设置页配置。
  - 设置页提供「发送测试邮件」按钮，一键验证配置是否可用。
  - 剧集更新通知：配合第三方平台插件（如蜜柑计划）发送番剧更新通知。
  - 通知服务支持多种通知类型。

### 4.15 作品信息服务（供插件使用）

- **描述**：供插件调用的第三方作品信息访问服务。
- **需求点**：
  - 统一的作品信息查询入口。
  - 插件可调用第三方作品信息平台进行查询。

### 4.16 设置与自定义

#### 4.16.1 系统设置（FR-SET-01）

- 系统级设置项管理。
- 启动时自动初始化系统设置。
- 控制台设置页：全局页头/页脚配置的加载与管理。

#### 4.16.2 自定义数据类型（FR-CUSTOM-01）

- **描述**：高级功能，允许用户/插件通过「自定义数据类型」定义新的内容结构，系统自动生成对应的管理能力（具体机制见设计文档）。
- 自定义数据支持标识与版本管理。
- 自动生成对应的管理功能（新增、编辑、删除、查询）。
- 自定义数据类型管理器：创建、监听变更、初始化。

### 4.17 主题与静态资源

#### 4.17.1 主题（FR-THEME-01）

- 网页端支持多主题（默认主题随系统一起发布）。
- 主题切换功能。
- 默认主题作品详情页：剧集序号选择、播放、通过网址参数指定剧集、封面展示。
- 主题下支持 ass 等字幕格式挂载。

#### 4.17.2 静态资源（FR-STATIC-01）

- 静态文件可通过网址访问（如 `/static/**`）。
- 支持从用户工作目录等位置加载静态文件。
- 字体目录：`statics/fonts`，提供获取所有字体地址的能力。

### 4.18 控制台（网页管理界面）

#### 4.18.1 概述（FR-CONSOLE-01）

- 网页管理控制台，Material 3 设计风格。
- 支持中英文界面。
- 响应式布局，侧边栏分组菜单：仪表盘 / 内容 / 用户 / 接口 / 系统 / 工具。

#### 4.18.2 功能页面清单

| 分组 | 页面 |
|------|------|
| 仪表盘 | 统计概览 |
| 内容 | 作品管理（列表/详情/新增/编辑/关系/同步/标签）、剧集管理（详情/新增/编辑）、附件管理（列表/上传/驱动/详情/关系/多选/选择）、音乐（专辑/歌曲）、命名规则管理 |
| 用户 | 登录、个人中心（资料/收藏/两步验证管理）、收藏页 |
| 系统 | 用户管理、角色管理（含权限授权）、插件管理（列表/详情/上传）、设置、任务（列表/详情）、关于 |
| 接口 | 全局搜索、主题相关 |

#### 4.18.3 关键交互需求

- 作品卡片根据剧集匹配进度呈现不同样式（进度条样式）。
- 视频预览：内置播放器，支持字幕、记住播放进度。
- 附件选择器：只有一个结果时自动选中；支持多关键词搜索。
- 图片裁剪后上传。
- 附件列表支持目录切换（面包屑导航）、排序、刷新、复制目录等。

### 4.19 运行监控与健康检查

- 系统运行状态监控（面向运维，管理员可查看详细状态）。
- 健康检查（管理员可查看组件运行情况）。
- 支持接入 Prometheus 监控（面向运维）。
- 关于页展示系统版本、运行环境等信息，可一键复制。

## 5. 非功能需求（NFR）

> 说明：本节中带技术词汇的条目面向开发与运维人员；对普通用户而言，只需知道系统在这些方面有明确的保障。

### 5.1 性能（NFR-PERF）

| 编号 | 需求 | 目标 |
|------|------|------|
| NFR-PERF-01 | 全局搜索响应 | 数十万资源下毫秒级响应（见 4.8 搜索） |
| NFR-PERF-02 | 附件目录刷新 | 增量同步，仅处理变更文件，合并重复刷新请求 |
| NFR-PERF-03 | 剧集/条目查询 | 常用数据缓存，命中缓存时查询零压力 |
| NFR-PERF-04 | 文件指纹计算 | 后台异步执行，不阻塞目录刷新 |
| NFR-PERF-05 | 流媒体播放 | 支持按需分段读取，拖动播放流畅 |

### 5.2 安全（NFR-SEC）

| 编号 | 需求 | 说明 |
|------|------|------|
| NFR-SEC-01 | 登录安全 | 登录凭证自动续期；可选两步验证 |
| NFR-SEC-02 | 路径防护 | 防止通过恶意文件路径绕过目录限制（含插件安装） |
| NFR-SEC-03 | 越权防护 | 防止修改/访问他人数据（见 4.2.2 用户管理） |
| NFR-SEC-04 | 注入防护 | 防止恶意代码注入（含数据导出场景） |
| NFR-SEC-05 | 远程请求防护 | 下载远程图片时校验目标地址，防止被利用 |
| NFR-SEC-06 | 密码保护 | 用户密码加密存储，绝不泄露 |
| NFR-SEC-07 | 文件隔离 | 附件只能访问自身存储目录内文件，防止越权读取（见 4.5.2 存储驱动安全） |
| NFR-SEC-08 | 插件安全 | 插件内部功能无删除能力；安装时校验（见 4.10.3 插件安全） |

### 5.3 可用性与可靠性（NFR-REL）

- 数据库升级：版本化迁移，无缝升级，不丢失数据。
- 日志：按天/大小自动滚动保存（单文件 10MB × 共 1GB × 保留 2 份）。
- 任务系统失败可追踪（任务状态/错误信息）。
- 导入流程失败自动回滚。

### 5.4 兼容性（NFR-COMP）

- **运行环境**：Windows / Linux / macOS（需 Java 21 或更高版本）。
- **数据库**：PostgreSQL 18 或更高版本（随安装包/镜像提供）。
- **浏览器**：现代浏览器（Chrome / Edge / Firefox / Safari 最新两个大版本）。
- **协议兼容**：兼容 Subsonic 协议，支持第三方音乐 App。
- **部署方式**：Docker 镜像、单文件运行、源码构建（面向开发者）。

### 5.5 可维护性（NFR-MAINT）

> 面向开发者。

- 单元测试覆盖率持续提升（目标 >80%，持续集成中自动统计）。
- 代码规范检查（Checkstyle 9.3）。
- 全量中文代码注释（服务实现类命名 `XxxService` + `DefaultXxxService`）。
- CHANGELOG.md 规范维护，提交改动需同步更新。
- 国际化文本统一来源管理。

### 5.6 可扩展性（NFR-EXT）

- 插件扩展能力体系（见 4.10.2）。
- 存储驱动抽象支持新存储类型扩展。
- 自定义数据类型支持动态扩展。
- 命名规则支持插件注入。

## 6. 技术架构

> 本章面向开发与部署人员，普通用户可跳过。

### 6.1 技术栈

| 层次 | 技术 | 版本 |
|------|------|------|
| 语言 | Java | 21 |
| 后端框架 | Spring Boot（WebFlux 响应式） | 4.0.1 |
| 构建 | Gradle | 8.14.5 |
| 数据库 | PostgreSQL | 18+ |
| 数据库访问 | R2DBC（响应式） | - |
| 数据库迁移 | db-migration（Flyway 风格） | - |
| 缓存 | 内存 / Redis（可切换、可关闭） | - |
| 搜索 | Lucene | - |
| 前端 | Vue 3 + Vite + Element Plus + FormKit + ArtPlayer + Pinia + vue-i18n | - |
| 前端构建 | pnpm | 10.32.1 |
| API 文档 | SpringDoc（springdoc-openapi） | - |
| 校验 | Checkstyle | 9.3 |
| 测试 | JUnit + Testcontainers | - |

### 6.2 模块划分

```
ikaros/
├── api/          # API 层：核心领域模型、枚举、操作接口、插件 API、扩展点
├── server/       # 服务端实现：核心模块、端点、存储、插件管理、搜索
│   └── src/main/resources/templates/simple   # 默认主题（git submodule）
├── console/      # Web 控制台前端（Vue 3）
│   └── packages/ # shared（共享类型）、api-client（API 客户端）
├── platform/     # 平台相关
├── config/       # Checkstyle 等配置
└── docs/         # 文档（含本 PRD）
```

### 6.3 关键设计

- **响应式架构**：全栈 WebFlux + R2DBC，非阻塞 IO。
- **函数式路由**：Spring WebFlux RouterFunction + SpringDoc 编程式 API 文档。
- **事件驱动**：作品/剧集/附件/标签变更通过事件监听器驱动索引重建、缓存更新、字幕匹配、通知等。
- **责任链模式**：目录绑定导入流程、剧集序号解析链。
- **插件隔离**：独立插件应用上下文（ClassLoader 隔离）。
- **缓存抽象**：统一缓存开关，内存/Redis 可切换。

### 6.4 部署形态

- **Docker**：`ikarosrun/ikaros` 官方镜像。
- **单文件运行**：`java -jar ikaros-server.jar`。
- **源码构建**：Gradle `buildFrontend` + `bootJar`。
