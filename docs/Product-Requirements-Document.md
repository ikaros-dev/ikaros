## 1. 产品概述

### 1.1 背景与问题

个人用户在管理 ACGMN（Anime 动画、Comic 漫画、Game 游戏、Music 音乐、Novel 小说）资源时，普遍面临以下痛点：

- **资源分散**：本地文件、网络驱动、云盘等各处存放，管理混乱。
- **识别困难**：大量资源文件名是罗马音/缩写，难以直观识别内容。
- **检索低效**：资源数量庞大（数十万级）时，缺乏毫秒级检索能力。
- **功能割裂**：元数据获取、字幕匹配、剧集绑定等需要多个工具协同，缺少统一平台。
- **扩展受限**：固定功能的产品无法覆盖用户多样化的个性化需求。

### 1.2 产品定位

Ikaros 是一款**自托管（Self-hosted）、面向个人用户的 ACGMN 内容管理系统（CMS）**，提供从资源接入、元数据管理、搜索、播放到收藏追踪的一站式管理能力。本体只提供最基础的核心功能，其余附加能力通过**插件系统**扩展。

### 1.3 产品目标

1. **统一管理**：所有 ACGMN 资源由统一平台管理，消除资源分散问题。
2. **元数据完备**：为条目提供名称、中文名、封面、简介、评分等信息，支持从第三方平台同步。
3. **毫秒级搜索**：即使数十万资源，也能提供毫秒级搜索响应。
4. **可扩展**：通过插件机制开放能力边界，社区共建生态。
5. **多端覆盖**：提供 Web 控制台，并支持 Windows、Android 等主流平台客户端。

### 1.4 非目标（Non-Goals）

- 不提供公网多用户 SaaS 服务（定位为个人使用，不建议公网访问）。
- 不直接提供内容下载/版权内容分发能力。
- 不内置具体第三方元数据源实现（由插件提供）。

### 1.5 免责声明

- 本程序为开源解决方案（AGPL-v3.0），源代码公开获取。
- 本程序用于辅助**个人**管理资源，类似 C/S 架构的文件管理器。
- 仅供个人使用，不建议允许公网访问；用户行为与程序及开发团队无关。

## 2. 目标用户与使用场景

### 2.1 目标用户

| 用户类型 | 描述 | 核心诉求 |
|----------|------|----------|
| ACGMN 收藏爱好者 | 拥有大量本地番剧、漫画、音乐、小说资源的个人用户 | 统一管理、快速检索、自动元数据 |
| 媒体服务器自建用户 | 熟悉自托管服务的用户（如 Jellyfin/Emby 用户） | 部署简单、可扩展、多端播放 |
| 开发者/贡献者 | 希望扩展 Ikaros 能力的开发者 | 插件开发、二次开发、API 接入 |

### 2.2 核心使用场景

1. **资源接入**：挂载本地磁盘/网络驱动目录，自动扫描、识别并绑定到条目。
2. **条目管理**：创建/编辑动画、漫画、游戏、音乐、小说等条目，维护元数据。
3. **资源绑定**：将目录/文件与条目剧集批量匹配（支持多种命名格式与正则规则）。
4. **搜索浏览**：通过名称、中文名、类型、标签等条件快速检索条目。
5. **收藏追踪**：标记想看/在看/看过/搁置/抛弃，评分评论，追踪追番进度。
6. **播放消费**：通过 Web/App 在线播放视频（支持字幕、进度记忆）。
7. **音乐聆听**：管理音乐专辑/歌曲，通过 Subsonic 协议接入第三方音乐播放器。
8. **通知推送**：剧集更新时通过邮件等渠道接收更新通知。

## 3. 术语定义

| 术语 | 英文 | 说明 |
|------|------|------|
| 条目 | Subject | ACGMN 内容的基本单位，如一部动画、一本漫画 |
| 剧集 | Episode | 条目的组成部分，如番剧的第 1 集 |
| 附件 | Attachment | 存储于本地的文件资源（视频、字幕、图片等） |
| 附件驱动 | Attachment Driver | 挂载本地目录/网络驱动的抽象，负责文件访问 |
| 绑定 | Binding | 将目录/文件与条目剧集建立关联关系 |
| 收藏 | Collection | 用户对条目的收藏状态（在看/看过等）及评分评论 |
| 条目关系 | Subject Relation | 条目之间的关联（前传、后传、同世界观、OST 等） |
| 标签 | Tag | 用户/系统为条目、附件添加的分类标记 |
| 元数据 | Metadata | 条目的描述信息（名称、封面、简介、评分等） |
| 插件 | Plugin | 扩展 Ikaros 能力的独立模块（JAR） |
| 正则规则 | Episode Sequence Regular | 从文件名解析剧集序号的规则 |
| 2FA/TOTP | Time-based One-Time Password | 基于时间的一次性密码（二步验证） |

### 4.2 认证与用户管理

#### 4.2.1 用户认证（FR-AUTH-01）

- **描述**：用户通过账号密码登录系统。
- **需求点**：
  - 支持用户名 + 密码认证（Basic 认证 / JWT Token）。
  - 登录成功后签发 **Access Token**（默认有效期 3 天）与 **Refresh Token**（默认有效期 3 个月）。
  - 支持 Token 刷新接口，Access Token 过期后可通过 Refresh Token 续期。
  - 支持 **TOTP 二步验证（2FA）**：登录凭据验证通过后，若用户已开启 2FA，需输入 6 位动态验证码（RFC 6238，HMAC-SHA1，30 秒周期）。
  - 个人中心支持 2FA 开启/关闭/重新绑定，支持 Authenticator 应用扫码（二维码）绑定。
  - 退出登录接口，删除当前账户后自动退出登录。

#### 4.2.2 用户管理（FR-AUTH-02）

- **描述**：管理员对系统用户进行管理。
- **需求点**：
  - 用户列表分页查询、创建、编辑、删除用户。
  - 支持更新用户名、昵称、密码。
  - 支持为用户分配角色。
  - 非管理员用户的菜单和按钮按权限动态显示。
  - 用户个人信息更新接口独立（`PUT /user/me` 使用 SecurityContext 认证用户而非请求体，防越权）。

#### 4.2.3 角色与权限（FR-AUTH-03）

- **描述**：基于 RBAC 模型的权限控制。
- **需求点**：
  - 系统内置角色：MASTER（主角色，默认拥有全部权限）。
  - 角色 CRUD，角色-权限（Authority）绑定管理。
  - 权限目标（auth target）细分到接口级别（如条目、剧集、附件、标签、用户、角色等模块）。
  - 提供细粒度授权目标，支持按模块配置角色权限。
  - 控制台明确权限提示并默认选择主角色。

### 4.3 条目（Subject）管理

#### 4.3.1 条目模型（FR-SUBJ-01）

- **描述**：条目是 ACGMN 内容的核心实体。
- **字段定义**：
  - `id`：UUID 主键。
  - `type`：类型枚举 — ANIME（动画）、COMIC（漫画）、GAME（游戏）、MUSIC（音乐）、NOVEL（小说）、REAL（真人）、OTHER（其他）。
  - `name`：名称（必填）。
  - `nameCn`：中文名称。
  - `infobox`：信息框（结构化元数据信息）。
  - `summary`：简介。
  - `nsfw`：是否成人内容（影响匿名搜索可见性）。
  - `airTime`：播出/发售时间。
  - `cover`：封面 URL（支持下载到本地缓存）。
  - `score`：综合评分（0-10）。

#### 4.3.2 条目操作（FR-SUBJ-02）

- **需求点**：
  - 条目 CRUD：新增、编辑、删除、详情查询。
  - 分页/条件查询：支持按名称（Base64 编码模糊查询）、中文名、类型、标签、评分排序、日期排序（空值排后）等条件组合查询。
  - 支持查询关键词格式：`属性:值` 冒号关键词格式（如 `type:ANIME`）。
  - 条目新增时自动检测剧集，无剧集时自动创建默认剧集条目。
  - 条目删除时级联清理关联的收藏、封面引用等。
  - 条目更新触发索引重建事件、封面变更事件、缓存更新。
  - 条目修改接口支持乐观锁，避免并发覆盖（更新失败返回 409 类错误）。

#### 4.3.3 条目关系（FR-SUBJ-03）

- **描述**：管理条目之间的关联关系。
- **关系类型**：OTHER、ANIME、COMIC、GAME、MUSIC、NOVEL、REAL、BEFORE（前传）、AFTER（后传）、SAME_WORLDVIEW（同世界观）、ORIGINAL_SOUND_TRACK（OST）、ORIGINAL_VIDEO_ANIMATION（OVA）、ORIGINAL_ANIMATION_DISC（OAD）。
- **需求点**：
  - 条目关系 CRUD 接口。
  - 控制台条目详情页以 Tab 展示不同关系类型。
  - 关系变更时监听并维护关联条目状态。

#### 4.3.4 条目同步（FR-SUBJ-04）

- **描述**：从第三方平台（如番组计划 Bangumi）同步条目数据。
- **需求点**：
  - 支持按平台 + 平台 ID 查询/拉取条目。
  - 第三方同步逻辑可重构、可扩展（由插件提供具体平台实现）。
  - 快速拉取条目后支持定位到对应条目。
  - 同步时自动下载封面到本地。
  - 并发同步时避免重复条目（幂等/去重）。
  - 同步收藏进度（如番组计划平台的收藏进度同步）。
  - 同步失败时保留原封面不更新。

### 4.4 剧集（Episode）管理

#### 4.4.1 剧集模型（FR-EP-01）

- **描述**：剧集是条目的子单元。
- **核心字段**：ID、所属条目 ID、剧集序号（支持小数）、分组、资源绑定关系。
- **剧集分组（EpisodeGroup）枚举**：MAIN（正片）、PROMOTION_VIDEO（PV）、OPENING_SONG（OP）、ENDING_SONG（ED）、SPECIAL_PROMOTION（SP）、SMALL_THEATER（小剧场）、LIVE（Live）、COMMERCIAL_MESSAGE（CM）、ORIGINAL_SOUND_TRACK（OST）、ORIGINAL_VIDEO_ANIMATION（OVA）、ORIGINAL_ANIMATION_DISC（OAD）、MUSIC_DIST1~5（音乐碟）、OTHER。

#### 4.4.2 剧集操作（FR-EP-02）

- **需求点**：
  - 剧集 CRUD（新增、编辑、删除、详情）。
  - 按条目 ID 查询剧集列表（含分页）。
  - 批量创建/更新剧集（支持插件按条目 ID 批量更新）。
  - 剧集排序（按序号排序，支持小数）。
  - 剧集序号支持 `1`、`01`、`1.5` 等格式。
  - 更新剧集时保持 ID 稳定（不因更新导致 ID 变化）。
  - 剧集查询支持缓存（内存/Redis）。

#### 4.4.3 剧集序号正则规则（FR-EP-03）

- **描述**：从文件名解析剧集序号的规则引擎。
- **需求点**：
  - 内置多种正则格式：`[01]`~`[100]`、`[EP01]`~`[EP100]`、`[01v2]`~`[100vX]`、` 01 `~` 99 `（空格包裹）、`EP01`、`-01-`、`_01_` 等。
  - 带前缀固定匹配：`[NCOP]`→OP、`[NCED]`→ED、`[SP]`→SP、`[CM]`→CM、`[OVA]`→OVA、`[OAD]`→OAD。
  - 带前缀序号匹配：`[NCOP01]`~`[NCOP100]`、`[NCED01]`~`[NCED100]` 等。
  - 规则支持优先级排序，通用兜底规则最低优先级。
  - 责任链模式：DB 规则与插件规则合并，统一按优先级执行。
  - 插件可通过 `EpisodeSequenceRegularPluginHook` 扩展自定义 Handler。
  - 控制台提供正则规则管理页面：列表、启用/禁用、编辑、删除、详情、测试匹配（输入文件名调用 match 接口验证结果）。

### 4.5 附件（Attachment）管理

#### 4.5.1 附件模型（FR-ATT-01）

- **描述**：附件是系统管理的文件资源。
- **核心字段**：ID、名称、类型（视频/字幕/图片等）、文件大小、SHA-1、逻辑路径、所属驱动、最后修改时间、创建/更新时间。

#### 4.5.2 附件驱动抽象（FR-ATT-02）

- **描述**：附件驱动是文件访问的统一抽象，支持挂载本地可访问目录、网络驱动。
- **需求点**：
  - 驱动类型：`LOCAL`（本地磁盘）、`PLUGIN`（插件提供的驱动类型）。
  - 驱动 CRUD：新增、编辑（配置修改后自动重新挂载）、删除、启用/禁用。
  - 挂载服务（AttachmentDriverMountService）：统一维护驱动目录映射、路径校验、附件根目录状态。
  - 挂载路径校验：拒绝不存在、不可访问、非目录的挂载路径。
  - 安全校验（v1.2.1）：
    - 可信根目录校验，阻止附件访问逃逸出驱动根目录。
    - 防止路径遍历访问驱动目录外文件。
    - 防止符号链接访问驱动目录外文件。
    - 动态目录解析只能访问已注册且可读的真实目录。
  - 驱动附件必须关联有效驱动 ID。
  - 插件可扩展附件驱动（响应式接口 AttachmentDriverFetcher）。

#### 4.5.3 附件操作（FR-ATT-03）

- **需求点**：
  - 附件分页/条件查询：名称模糊查询（支持空格多关键词）、按名称/更新时间/文件大小排序。
  - 附件上传：普通上传、分片上传（Fragment Upload）、图片裁剪上传。
  - 附件删除（删除时校验引用关系）。
  - 附件流式读取：普通附件与驱动附件的 range 流读取（支持 HTTP Range 分段）。
  - 附件 URL：独立解析接口，支持条件参数查询、带条件 URL 获取。
  - SHA-1：后台异步计算（避免阻塞），计算期间校验文件状态，按文件大小和修改时间判断是否需要重算。
  - 目录刷新：递归刷新（可增量同步，仅处理新增/变更/删除附件），合并同一驱动并发刷新请求。
  - 附件标签：支持为附件打标签。

#### 4.5.4 附件关系与引用（FR-ATT-04）

- **描述**：附件之间的关联及附件与条目的引用。
- **需求点**：
  - 附件关系：手动绑定视频附件和字幕附件；视频字幕自动匹配（当剧集附件引用新增时，按附件名模糊匹配同名字幕文件，支持驱动类型与普通类型，支持 ssa 后缀）。
  - 附件引用：附件与条目/剧集的引用关系管理（如封面引用、剧集资源引用、用户头像引用）。
  - 批量绑定/移除绑定：文件名→剧集序号解析后批量匹配（支持三位数、中括号内 0~999.0 浮点数）。
  - 附件关系变更事件监听。

### 4.6 目录绑定工作流（Binding）

#### 4.6.1 概述（FR-BIND-01）

- **描述**：将本地目录（含资源文件）与条目/剧集自动绑定的**半自动化导入工作流**，采用责任链模式按序执行，任一步骤失败时逆序回滚已完成步骤。

#### 4.6.2 工作流步骤

| 步骤 | 说明 |
|------|------|
| CleanDirectoryNameStep | 清洗目录名（去除无效字符） |
| ParseDirectoryNameStep | 解析目录名，提取条目名称、剧集序号等信息 |
| ListFilesStep | 列出目录内文件 |
| FindSubjectInfoStep | 查找本地已有条目信息 |
| FetchAndCreateSubjectStep | 拉取元数据并创建条目 |
| SyncSubjectByPlatformIdStep | 按平台 ID 同步条目（对接第三方平台） |
| CreateSubjectTagsStep | 创建条目标签 |
| ProcessSpSubdirectoriesStep | 处理 SP 等特殊子目录 |
| BindEpisodesStep | 批量绑定剧集与附件 |

#### 4.6.3 需求点

- 目录绑定工作流实体持久化（DirectoryBindingWorkflowEntity），支持查询工作流状态。
- 步骤执行状态追踪（RUNNING / SUCCESS / FAIL）与错误信息记录。
- 失败自动回滚已成功步骤（逆序）。
- 支持跳过条件（shouldSkip）。

### 4.7 收藏（Collection）

#### 4.7.1 条目收藏（FR-COLL-01）

- **描述**：用户对条目的收藏状态管理。
- **收藏类型（CollectionType）**：WISH（想看）、DOING（在看）、DONE（看过）、SHELVE（搁置）、DISCARD（抛弃）。
- **需求点**：
  - 收藏 CRUD：新增收藏、更新收藏类型、移除收藏。
  - 收藏评分（0-10）与评论。
  - 按条件查询收藏：分页、按日期查询、按收藏类型查询、按条目 ID 查询。
  - 收藏聚合接口优化（批量查询效率）。
  - 新条目收藏时自动创建剧集收藏（默认全未看）。
  - 条目移除时清理对应收藏。
  - 条目收藏类型变更时联动更新剧集收藏状态。

#### 4.7.2 剧集收藏（FR-COLL-02）

- **描述**：追踪每条剧集的观看进度。
- **需求点**：
  - 标记单集已看/未看（"看完"按钮动态显示）。
  - 批量标记。
  - 剧集列表收藏（如歌单收藏对接剧集列表收藏）。
  - 收藏页默认条件为"在看"。

#### 4.7.3 历史记录（FR-COLL-03）

- 支持历史记录（收藏）条件查询接口，支持按日期范围查询。

### 4.8 搜索（Search）

#### 4.8.1 全局索引（FR-SEARCH-01）

- **描述**：基于 Lucene 的毫秒级全文检索。
- **需求点**：
  - 条目索引：名称、中文名、类型、标签、封面等字段入索引。
  - 索引重建接口（POST `indices/subject`）与索引初始化器。
  - 条目新增/更新/删除/标签变更时通过事件监听增量维护索引。
  - 支持按需开关 Lucene 索引初始化。
  - 索引启动时初始化全部条目（可修复初始化不全问题）。

#### 4.8.2 搜索能力（FR-SEARCH-02）

- 分页搜索条目，返回条目 ID、名称、封面等命中信息（SubjectHint）。
- 匿名访问可搜索非 NSFW 条目。
- 支持关键词组合与属性限定。

### 4.9 标签（Tag）

#### 4.9.1 标签管理（FR-TAG-01）

- **描述**：为条目/附件提供标签能力。
- **需求点**：
  - 标签 CRUD（创建时检测唯一性并关联用户 ID）。
  - 标签类型区分（TagType）。
  - 条目标签的查询、新增、移除。
  - 自定义标签高亮显示。
  - 附件标签支持（服务端）。
  - 插件可通过 TagOperate 查询/新增标签（出于安全，插件内部接口移除删除方法）。
  - 条目标签更新时触发索引重建，标签计入搜索索引。

### 4.10 插件系统（Plugin）

#### 4.10.1 插件生命周期（FR-PLUGIN-01）

- **描述**：插件是 Ikaros 能力扩展的核心机制，本体只提供基础功能。
- **需求点**：
  - 插件安装：JAR 上传安装（校验路径穿越/文件名注入风险）、仓库安装。
  - 插件卸载、启用、禁用、升级。
  - 插件配置：ConfigMap 形式的配置读写（创建/更新/变更事件）。
  - 插件运行模式：`deployment`（部署模式）/ 开发模式（IkarosDevelopmentPluginLoader）。
  - 插件版本与 Core 版本兼容性校验。
  - 插件 JAR 加载：YamlPluginLoader、IkarosJarPluginLoader、FixedPathDevelopmentPluginRepository。
  - 插件应用上下文隔离（PluginApplicationContext），支持共享上下文。
  - 插件异常处理（安装失败、升级失败、禁用状态访问等）。

#### 4.10.2 插件扩展点（FR-PLUGIN-02）

| 扩展点 | 说明 |
|--------|------|
| 附件驱动 Fetcher | 插件提供自定义附件驱动实现（响应式） |
| 附件访问 URL Provider | AttachmentAccessUrlProvider 抽象接口 |
| 元数据 Operator（MetaOperate） | 插件调用三方元数据源查询条目 |
| 标签 Operator（TagOperate） | 插件查询/新增标签 |
| 条目同步器（SubjectSynchronizer） | 插件对接三方平台同步条目 |
| 剧集序号正则 Handler | 插件注册自定义文件名解析规则到责任链 |
| 任务（PluginTask） | 插件注册后台任务 |
| 自定义路由/端点 | 插件通过 CustomEndpoint 注册 REST 端点 |
| 自定义 Scheme | 插件定义自定义实体结构（Custom Scheme） |

#### 4.10.3 插件安全（FR-PLUGIN-03）

- 插件的内部接口移除所有删除方法（安全性考虑）。
- 插件访问受权限控制（AllowPluginOperate）。
- 插件 JAR 上传路径穿越和文件名注入防护。

### 4.11 音乐模块（Music）

#### 4.11.1 概述（FR-MUSIC-01）

- **描述**：v1.2 新增的音乐资源管理模块。
- **核心实体**：
  - `Music`：音乐专辑（对应条目模型中的音乐类型）。
  - `Song`：歌曲（对应剧集/剧集列表模型）。

#### 4.11.2 功能需求

- 音乐专辑管理：专辑列表、详情（曲目列表）、新增、编辑、删除。
- 歌曲管理：歌曲增删改查。
- 歌单：歌单对应剧集列表（EpisodeList），歌单收藏对接剧集列表收藏。
- 音乐碟分组：MUSIC_DIST1~5。
- 控制台音乐页面：专辑管理、歌曲管理及多语言支持。

### 4.12 Subsonic 协议兼容（Subsonic）

#### 4.12.1 概述（FR-SUBSONIC-01）

- **描述**：兼容 Subsonic 开放 API，允许任意 Subsonic 客户端（如 DSub、音流等）接入播放音乐。
- **路由**：`/rest/*` 路径统一路由分发。

#### 4.12.2 支持的 API

| 分类 | 端点 |
|------|------|
| 浏览 | getArtists / getArtist / getAlbum / getSong / getAlbumList2 |
| 播放 | stream（音频流）/ getCoverArt（封面） |
| 歌单 | getPlaylists / getPlaylist / createPlaylist / deletePlaylist |
| 其他 | search2 / scrobble / ping |

### 4.13 任务系统（Task）

#### 4.13.1 概述（FR-TASK-01）

- **描述**：后台任务调度与执行管理。
- **需求点**：
  - 任务模型：任务状态（TaskStatus）、执行进度、日志。
  - 线程池配置：core-pool-size=4、max=40、队列 10000，可配置。
  - 任务 CRUD/查询（FindTaskCondition 条件查询）。
  - 后台任务接口优化（分页、状态过滤）。
  - 支持插件注册任务（PluginTask）。
  - 任务初始化器（TaskInit）与系统任务。
  - 运行日志按天和大小分割（10MB/文件，总 1GB，保留 2 份历史）。

### 4.14 通知系统（Notify）

#### 4.14.1 邮件通知（FR-NOTIFY-01）

- **描述**：通过邮件发送系统通知。
- **需求点**：
  - SMTP 邮件设置（Host、端口、账号、密码等），支持设置页配置。
  - 邮件测试按钮：设置页一键发送测试邮件。
  - 剧集更新通知：配合第三方平台插件（如蜜柑计划）发送番剧更新通知。
  - 通知服务支持多种通知模型（NotifyService / NotifyEndpoint）。

### 4.15 元数据服务（Meta）

- **描述**：供插件调用的三方元数据访问服务。
- **需求点**：
  - MetaService / MetaInfoService：统一元数据查询入口。
  - MetaOperate：插件可调用三方元数据插件进行条目查询。
  - 端点：MetaInfoEndpoint。

### 4.16 设置与自定义（Setting / Custom）

#### 4.16.1 系统设置（FR-SET-01）

- 系统级设置项管理（SettingService）。
- 启动时初始化系统设置（SystemSettingInitListener）。
- 控制台设置页：全局 header/footer 配置加载与管理。

#### 4.16.2 自定义 Scheme（FR-CUSTOM-01）

- **描述**：参考 Kubernetes CRD 模式，允许通过自定义 Scheme 定义新的实体结构（Custom Entity + CustomMetadata），系统动态生成对应数据表与 CRUD 能力。
- 自定义实体支持 GroupVersionKind 标识。
- 自定义路由（CustomRouterFunctionFactory）自动生成 REST 端点。
- 自定义 Scheme 管理器：创建、监听（Watcher）、初始化。

### 4.17 主题与静态资源（Theme / Statics）

#### 4.17.1 主题（FR-THEME-01）

- Web 端多主题支持（默认主题通过 git submodule 管理）。
- 主题切换与主题服务（ThemeService / DefaultThemeService）。
- 默认主题条目详情页：剧集序号选择、播放逻辑、URL 参数指定剧集、封面展示。
- 主题下 ass 字幕挂载支持。

#### 4.17.2 静态资源（FR-STATIC-01）

- 静态文件服务：`/static/**` URL 访问。
- 支持从以下目录加载静态文件：用户工作目录 `statics` 目录等。
- 字体目录：`statics/fonts`，提供获取所有字体 URL 的接口。
- StaticEndpoint：提供静态资源访问端点。

### 4.18 控制台（Console）

#### 4.18.1 概述（FR-CONSOLE-01）

- Web 管理控制台，Vue 3 + Element Plus + FormKit 构建，Material 3 Design 风格登录页。
- 支持中英文国际化（en.yaml / zh-CN.yaml）。
- 响应式布局，侧边栏分组菜单：Dashboard / 内容 / 用户 / 接口 / 系统 / 工具。

#### 4.18.2 功能页面清单

| 分组 | 页面 |
|------|------|
| Dashboard | 仪表盘（统计概览） |
| 内容 | 条目管理（列表/详情/新增/编辑/关系/同步/标签）、剧集管理（详情/新增/编辑）、附件管理（列表/上传/驱动/详情/关系/多选/选择）、音乐（专辑/歌曲）、正则规则管理 |
| 用户 | 登录、个人中心（资料/收藏/TOTP 管理）、收藏页 |
| 系统 | 用户管理、角色管理（含权限授权）、插件管理（列表/详情/上传）、设置、任务（列表/详情）、关于 |
| 接口 | 全局搜索、主题相关 |

#### 4.18.3 关键交互需求

- 条目卡片根据剧集匹配进度呈现不同样式（进度条样式）。
- 视频预览：ArtPlayer 播放器，支持字幕、进度记忆。
- 附件选择器：只有一个结果时自动选中；支持多关键词搜索。
- 图片裁剪上传（Cropperjs）。
- 附件列表支持目录切换（面包屑）、排序、刷新、复制目录等。
- 通用消息对话框组件；加载中提示。
- 未授权提示明确化；403 页面、404 页面。
- 登录页 2FA 分步认证流程。

### 4.19 监控与运维（Actuator / 健康检查）

- Spring Boot Actuator 全端点暴露（`*`）。
- 健康检查（含组件健康，支持角色限制为 MASTER 查看详情）。
- Prometheus 指标聚合 API 支持。
- 应用信息贡献（版本、Git 提交、OS、Java 环境等），关于页可复制环境信息。
- Redis 被禁用时排除其健康检查自动配置。

## 5. 非功能需求（NFR）

### 5.1 性能（NFR-PERF）

| 编号 | 需求 | 目标 |
|------|------|------|
| NFR-PERF-01 | 全局搜索响应 | 数十万资源下毫秒级响应 |
| NFR-PERF-02 | 附件目录刷新 | 增量同步，仅处理变更文件，合并并发刷新请求 |

| NFR-PERF-05 | 流媒体播放 | 支持 HTTP Range 分段读取，拖动播放流畅 |

### 5.2 安全（NFR-SEC）

| 编号 | 需求 | 说明 |
|------|------|------|
| NFR-SEC-01 | 认证安全 | JWT + Refresh Token 双令牌；可选 TOTP 2FA |
| NFR-SEC-02 | 路径穿越防护 | Zip Slip、附件 fsPath、插件 JAR 上传路径穿越修复 |
| NFR-SEC-03 | 越权防护 | BOLA 修复（PUT /user/me 用 SecurityContext 认证） |
| NFR-SEC-04 | 注入防护 | Migration 导出 SQL 注入修复 |
| NFR-SEC-05 | SSRF 防护 | 条目封面 URL 下载使用 SsrfUtils 校验 |
| NFR-SEC-06 | 密码存储 | UserEntity.password 添加 @JsonIgnore，禁止序列化泄漏 |
| NFR-SEC-07 | 附件隔离 | 可信根目录校验 + 符号链接防护 + 动态目录解析白名单 |
| NFR-SEC-08 | 插件安全 | 插件内部接口无删除方法；插件安装校验 |

### 5.3 可用性与可靠性（NFR-REL）

- 数据库迁移：db-migration 版本化 SQL（Flyway 风格），无缝升级。
- 日志：按天/大小滚动分割（10MB × 总 1GB × 保留 2 份）。
- 任务系统失败可追踪（任务状态/错误信息）。
- 工作流失败自动回滚。

### 5.4 兼容性（NFR-COMP）

- **数据库**：PostgreSQL 18+（v1.1 起移除 H2）。

- **协议兼容**：Subsonic API 兼容第三方客户端。
- **部署**：Docker 镜像、Fast Jar 单文件运行、源码构建（Gradle）。

### 5.5 可维护性（NFR-MAINT）

- 国际化文本统一来源管理。

### 5.6 可扩展性（NFR-EXT）

### 6.1 技术栈

| 层次 | 技术 | 版本 |
|------|------|------|

| 数据库 | PostgreSQL | 18+ |
| 数据库访问 | R2DBC（响应式） | - |

| 前端 | Vue 3 + Vite + Element Plus + FormKit + ArtPlayer + Pinia + vue-i18n | - |

| API 文档 | SpringDoc（springdoc-openapi） | - |
| 校验 | Checkstyle | 9.3 |
| 测试 | JUnit + Testcontainers | - |

### 6.2 模块划分

```
ikaros/
├── api/          # API 层：核心领域模型、枚举、操作接口、插件 API、扩展点
├── server/       # 服务端实现：核心模块、端点、存储、插件管理、搜索
│   └── src/main/resources/templates/simple   # 默认主题（git submodule）
├── console/      # Web 控制台前端（Vue 3）
│   └── packages/ # shared（共享类型）、api-client（API 客户端）
├── platform/     # 平台相关
├── config/       # Checkstyle 等配置
└── docs/         # 文档（含本 PRD）
```

### 6.3 关键设计

- **响应式架构**：全栈 WebFlux + R2DBC，非阻塞 IO。
- **函数式路由**：Spring WebFlux RouterFunction + SpringDoc 编程式 API 文档。
- **事件驱动**：条目/剧集/附件/标签变更通过事件监听器驱动索引重建、缓存更新、字幕匹配、通知等。
- **责任链模式**：目录绑定工作流、剧集序号解析链。
- **插件隔离**：独立插件应用上下文（ClassLoader 隔离）。
- **缓存抽象**：统一缓存开关，内存/Redis 可切换。

### 6.4 部署形态

- **Docker**：`ikarosrun/ikaros` 官方镜像。
- **Fast Jar**：`java -jar ikaros-server.jar` 单文件运行。
- **源码构建**：Gradle `buildFrontend` + `bootJar`。

| 插件生态不足 | 中 | 完善插件扩展点文档与示例，降低开发门槛 |
| 数据库强依赖 PostgreSQL 18 | 中 | 提供 Docker 一键部署与迁移文档 |
| 响应式编程复杂度 | 中 | 统一编码规范、Checkstyle、测试覆盖 |
| 第三方平台接口变更 | 中 | 平台同步逻辑插件化，接口变更隔离在插件内 |
| 大资源量下的性能 | 低 | 增量索引、异步 SHA1、缓存、索引优化 |

---

## 10. 成功指标（建议）

- 搜索 P99 响应时间 < 100ms（十万级条目）。
- 附件目录刷新吞吐：万级文件增量刷新 < 1 分钟。
- 单元测试覆盖率 ≥ 80%。
- 插件扩展点数量与第三方插件活跃度。
- 版本迭代频率与 issue 关闭率。
